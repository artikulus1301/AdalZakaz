# AdalZakaz

Надстройка для малых онлайн-продавцов Тараза. Не даёт ошибке в карточке товара или в обработке заказа
превратиться в претензию: у каждого товара есть проверенный паспорт, у каждого заказа — единая история
с доказательствами, а каждая претензия рассматривается по закону и в срок.

Вместо Telegram-ботов сделано мультимодальное веб-приложение:

| Кто | Где | Что умеет |
|---|---|---|
| Продавец | `/` (панель, вход по паролю) | паспорта товаров, заказы, резерв, оплата, видео упаковки, претензии, аналитика, правила |
| Покупатель OLX / соцсетей | `/o/<токен>` (kk/ru) | что куплено, условия возврата простым языком, претензия **текстом, фото/видео и голосом**, вопрос продавцу |
| Любой посетитель | `/p/<id>` (kk/ru) | страница-паспорт товара: ссылка и QR для объявления OLX или профиля Instagram |

Мультимодальность: текст (ru, kk, смешанная речь), фото (модель Qwen со зрением сверяет фото товара с паспортом и
описывает фото из претензии), голос (запись в браузере → WAV 16 кГц → omni-модель Qwen), видео (видео упаковки
и видео покупателя хранятся в журнале доказательств с SHA-256).

## Запуск

```powershell
.\run.ps1
```

Или вручную (нужен Python 3.11):

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env      # впишите LLM_API_KEY (ключ xKiro)
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Откройте http://localhost:8000. Пароль по умолчанию — `demo`. При первом запуске создаются демо-данные:
5 товаров, заказы из Instagram, Telegram, OLX, WhatsApp и Kaspi, три претензии и один заказ,
отклонённый из-за нехватки остатка.

**Без ключа** всё работает: вместо модели подставляются детерминированные эвристики, а каждый
такой черновик помечен как «демо-эвристика». С ключом xKiro (`https://api.xkiro.com/v1`, OpenAI-совместимый API) подключаются
`qwen/qwen3.7-plus:free` (текст), `qwen/qwen3-vl-plus:free` (фото) и `qwen/qwen3.8-omni-flash:free` (речь).
Модели и провайдер меняются в `.env` (`LLM_*`).

Чтобы открыть страницу покупателя с телефона, укажите в `PUBLIC_BASE_URL` IP компьютера
(например, `http://192.168.1.10:8000`). Запись голоса в браузере работает только на `localhost` или
по HTTPS.

Тесты: `.venv\Scripts\python -m pytest -q`

## Остатки вариантов и частичные возвраты

- В карточке товара откройте **«Остатки по размерам и цветам» → «Настроить размеры и цвета»**.
  Укажите фактическое количество каждой комбинации, например `42 / белый` и `42 / чёрный`.
  Сумма становится общим остатком; резерв, отмена, отправка и возврат учитывают выбранный вариант.
  Существующий вариант можно снять с продажи остатком `0`; его название сохраняется для истории заказов.
- При первом включении учёта по вариантам не должно быть активного резерва по товару:
  сначала завершите или отмените такие заказы. Приложение не угадывает, какие размеры зарезервированы.
  Старые товары сохраняют общий остаток, пока продавец не распределит его вручную. В заказе это явно отмечено.
- В новом заказе размер/цвет выбирается из списка. Неизвестный вариант и отсутствие выбора
  при нескольких вариантах отклоняются на сервере. Наличие конкретного размера проверяется после настройки его остатка.
- При подтверждении претензии выберите **одну позицию заказа и количество**. Для другой позиции
  создайте отдельную претензию. Возврат денег ограничен стоимостью выбранного количества и учитывает
  предыдущие возвраты по позиции и заказу. На склад возвращается только выбранное количество;
  повторная команда или другая претензия не могут повторно оприходовать уже возвращённые единицы.
- Если старый заказ не содержит размер/цвет, а товар уже переведён на учёт по вариантам,
  при возврате на склад нужно проверить товар и выбрать вариант вручную.

Денежные показатели — данные внутреннего учёта, а не автоматический банковский перевод:

| Показатель | Что считается |
|---|---|
| Сумма заказов | Все заказы, кроме отменённых |
| Подтверждено оплат | Заказы с подтверждённой оплатой, включая оплаченные, но отменённые |
| Ожидается оплата | Неоплаченные заказы, кроме отменённых |
| Оплаты за вычетом возвратов | Подтверждённые оплаты минус зарегистрированные возвраты денег |

При запуске существующая SQLite-база обновляется добавлением таблиц и полей.
Старые остатки и версии паспортов сохраняются. Старые события оприходования учитываются
при защите от повторного возврата. Старый денежный возврат по многопозиционному заказу без
указания позиции требует ручной сверки перед регистрацией следующего денежного возврата.

## Заказ из сообщения или голосового

В «Сводке» и «Заказах» нажмите **«Из сообщения / голоса»**. Вставьте, например:
«Нужны белые кроссовки 42 размера, доставка завтра». Выберите канал и нажмите
«Разобрать сообщение». Можно передать несколько позиций через точку с запятой.

Помощник предлагает товар, размер / цвет, количество, контакты и пожелание по получению.
Цена и доступность берутся из текущего каталога. Неизвестные товары, неоднозначные модели,
недостающие сведения и общий остаток без учёта размеров показываются для ручной проверки.
Без ключа модели используется ограниченный локальный разбор; источник виден на экране.
Подключённая текстовая модель выделяет фрагменты сообщения, а программа проверяет их
и сопоставляет с каталогом. Контакты, распознанные локально, обезличиваются перед текстовой моделью.

Для голосового сообщения запишите голос или загрузите аудиофайл (до 2 минут и 10 МБ).
Браузер преобразует его в WAV 16 кГц моно. По умолчанию речь распознаётся локально
через Whisper на CPU. Установите `pip install -r requirements-voice.txt` и выполните
`python -m app.ai.speech` для предварительной загрузки модели (первый запуск требует
интернета и места на диске). `ASR_LOCAL_MODEL=base` — компактная многоязычная модель;
для более высокого качества можно выбрать `small`, учитывая расход памяти и время обработки.
Расшифровку нужно проверить, особенно размер, количество, имена и смешанную речь.
Её можно исправить и разобрать повторно. Микрофон работает на localhost или HTTPS.
Аудио этого сценария не сохраняется как доказательство заказа.

Текстовый ИИ подключается отдельно через `LLM_API_KEY`. При `ASR_PROVIDER=llm`
аудио отправляется провайдеру `LLM_BASE_URL` в модель `LLM_SPEECH_MODEL`;
провайдер должен поддерживать `input_audio`. В проверенном подключении xKiro
модели Qwen отвечали отказом на аудио, поэтому одного ключа xKiro для речи недостаточно.
Отказ сервиса не принимается за расшифровку. Локальный ASR не требует API-ключа.

Нажмите **«Проверить и дополнить»**, исправьте поля и подтвердите заказ. До этого момента
резерва нет. При подтверждении остаток и цена проверяются заново в одной транзакции;
повторное подтверждение того же черновика возвращает существующий заказ. При нехватке
остатка можно исправить позиции и повторить подтверждение. «Доставка завтра» сохраняется
как пожелание, а согласование адреса и окна остаётся отдельным шагом.

## Adal Copilot — чат-помощник продавца

Один продавец не успевает следить за всеми разделами. Поэтому в меню есть отдельная страница **«Adal Copilot»**:
чат, которому можно задать вопрос или поручить дело.

- **Вопрос** («Сколько у нас сегодня новых заказов?», «Какие претензии горят?», «Что заканчивается на складе?»):
  Copilot находит данные в ядре и отвечает. Количества и суммы считает программа, а не модель.
  Под ответом видны источники (номера заказов, претензий, товаров); они открывают карточку.
- **Поручение** («Подтверди оплату AZ-000004, операция 778899», «Отмени их, покупатель не оплатил»):
  Copilot показывает план, то есть to-do список шагов, и ждёт кнопки **«Одобрить и выполнить»**.
  До одобрения ничего не меняется. Выполняются только одобренные шаги, по порядку, каждый через команды ядра
  со всеми его проверками. Повторное нажатие не выполняет план второй раз. План действует 30 минут.
- Шаги, которые ядро не пропустит (нет видео упаковки, не подтверждён адрес, номер операции не указан),
  видны в плане заранее с причиной и не выполняются. Если шаг по заказу не прошёл, остальные шаги по этому
  заказу пропускаются.
- Что умеет выполнять: сменить статус заказа, подтвердить оплату (номер операции должен быть в сообщении
  продавца), подтвердить адрес и окно доставки, отправить сообщение покупателю (в теневом режиме — только
  текст продавца; текст проверяет guard), закрыть претензию с решением, установить остаток, забрать заказы Kaspi.
- Что **не** делает: решения по претензиям, возвраты денег, правила и правки паспортов — это решает человек
  в своих разделах.
- Можно ссылаться на прошлый ответ: «Какие заказы ждут оплаты?» → «Отмени их».
- Прежние диалоги сохраняются: список слева (на телефоне — кнопка «Диалоги»), к любому можно вернуться.
- Номера заказов и претензий в ответах кликабельны и открывают карточку.
- Скорость: разбор запроса моделью и подготовка ответа идут параллельно. Если модель поняла запрос так же, как
  локальный разбор, и поиск вернул те же данные, готовый ответ отдаётся сразу; иначе пересчитывается.

Модель — `LLM_COPILOT_MODEL` (по умолчанию `qwen/qwen3.8-max:free`), ключ тот же `LLM_API_KEY`.
Без ключа Copilot работает на локальном разборе: ответы собираются по шаблону, поручения распознаются по глаголам.

**RAG.** У xKiro нет моделей эмбеддингов, поэтому поиск локальный и состоит из двух слоёв (`app/ai/copilot_rag.py`):
1. Точные выборки SQL по фильтрам запроса (период, статус, канал, оплата, номера). Отсюда берутся числа.
2. BM25 по базе знаний: заказы, товары, претензии, правила возврата и справка по приложению. Индекс
   перестраивается только при изменении данных.

Модель сначала разбирает запрос в фильтры, затем получает только найденные фрагменты и пишет ответ или план.
Имена, телефоны и адреса покупателей в модель не передаются, а тексты покупателей помечены как данные.
Код проверяет каждый шаг плана: действие из белого списка, объект упомянут в запросе, платёжные данные и адрес
взяты из сообщения продавца. После этого весь план прогоняется в ядре в транзакции с откатом.

## Архитектура

```
Каналы ─► Коннекторы ─► Очередь событий (inbox, ключ идемпотентности) ─► Ядро (без ИИ)
 Kaspi API      kaspi.py                                              паспорт (версии), остаток+резерв,
 OLX/соцсети    manual.py (+ страница заказа)                          статусы, оплата из источника,
                                                                      правила возврата + таймер 10 дней,
                                                                      журнал доказательств
                                     факты ▼                ▲ утверждённое человеком
                         Оркестратор ИИ (контекст = 1 заказ) ─► Панель продавца
                                     ▼
                         LLM — меняемый модуль (app/ai/llm.py, сейчас Qwen через xKiro)
```

```
app/
  core/            ядро без ИИ — единственный источник фактов
    passport.py    обязательные поля по категории, неизменные версии, проверка без ИИ
    inventory.py   единый остаток: атомарный резерв, без свободного остатка заказ не принимается
    orders.py      очередь входящих, статусы и переходы, оплата только из платёжного источника
    rules.py       правила возврата (версии, утверждение юристом), допустимые решения
    claims.py      претензии: срок 10 календарных дней, решение человека, возврат денег один раз
    evidence.py    файлы под SHA-256
    metrics.py     метрики пилота
  ai/
    llm.py         клиент OpenAI-совместимого API (xKiro): JSON, фото, речь
    orchestrator.py задачи ИИ + эвристики-заглушки, сохранение черновиков
    guard.py       сверка черновика с ядром: цена, гарантия, отказ, обещание денег
    redact.py      обезличивание: имя, телефон, адрес, ИИН, карта, IBAN, e-mail
    copilot.py     Adal Copilot: разбор запроса, ответ, план (to-do), одобрение и пошаговое выполнение
    copilot_rag.py RAG для Copilot: точные выборки из ядра + BM25 по базе знаний
  connectors/      kaspi.py (API или демо), manual.py
  main.py          FastAPI: панель, публичные страницы, API
static/            интерфейс без сборки (ванильный JS)
tests/             тесты ядра и защитных механизмов
```

## Как ядро и ИИ выполняют требования проекта

| Требование | Где реализовано |
|---|---|
| Паспорт с обязательными полями (состав, бренд, страна, размеры, цена, kk/ru) | `core/passport.py`: `REQUIRED_BASE` и поля, которые добавляет категория |
| Заказ хранит версию паспорта, по которой продан товар | `order_items.passport_version`; в панели есть пометка «паспорт обновлён после продажи» |
| Один товар не продаётся дважды | `inventory.reserve`: один атомарный `UPDATE … WHERE stock - reserved >= qty` |
| Скриншот не подтверждает оплату | `orders.confirm_payment`: только `kaspi_api`, `bank_statement`, `payment_provider`, `cash_register`; сумма должна совпасть; номер операции нельзя использовать дважды |
| Видео упаковки как доказательство | статус «Собран» нельзя поставить без видео или фото упаковки |
| Адрес подтверждается до отправки | статус «Передан в доставку» нельзя поставить без подтверждённого адреса и окна доставки (кроме Kaspi) |
| Срок ответа — 10 календарных дней | `claims.create` считает дедлайн; таймер и просрочки видны в панели и метриках |
| Решение о возврате принимает человек | ИИ только предлагает тип претензии; человек подтверждает тип и состояние товара; `rules.validate_decision` отклоняет решения, которых нет среди допустимых |
| Нет «возврату не подлежит» без основания | отказ возможен, только если правило это допускает, и с обоснованием не короче 40 символов; guard блокирует такие фразы в черновиках |
| Повтор команды не создаёт второй возврат или платёж | ключи идемпотентности в `events`, `UNIQUE(refunds.claim_id)`, `client_id` у претензии с публичной страницы |
| Факты берутся не из памяти модели | модель получает только контекст из ядра; перед отправкой guard сверяет цены и гарантию |
| Входящее сообщение — данные, а не инструкция | системный промпт и отдельные поля `buyer_message` / `claim_text` |
| Обезличивание; в запрос идёт один заказ | `redact.py`, `orchestrator.order_context` |
| Теневой режим → черновики | переключатель в разделе «Правила и ИИ»; в теневом режиме отправка запрещена на сервере |
| Информирование об ИИ (ст. 21) и о съёмке упаковки | блоки на страницах покупателя |
| Не распознаём эмоции и лица, не оцениваем покупателя | запрет в системном промпте; таких функций нет |
| Kaspi-покупателей не уводим на внешние страницы | для заказов Kaspi публичная ссылка не создаётся |
| Причина возврата → правка паспорта | «Аналитика» → «Разобрать причины» → «Утвердить правку» создаёт новую версию паспорта |
